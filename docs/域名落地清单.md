## 二、必须你在控制台做的 3 件事（我无法代操作）

### 1. 域名实名认证（最先做，否则**连 DNS 都改不了**）✅ 已完成 2026-11-11

> ✅ **本步已完成**：实名认证已通过，公网 `NS` 查询正常返回，`serverHold` 已解除。以下内容保留作排查备查，直接跳到第 2 步即可。

阿里云官方口径：所有域名必须完成实名认证才能正常解析；未认证会被注册局置为 `serverHold`，**网站无法访问，且此时无法修改 DNS 服务器**。所以这不是「最好先做」，而是「不做，第 2 步的按钮点不动」。

- 实名认证是**两步**，不是只传一张身份证：
  1. 创建并认证**信息模板**（域名持有者资料，提交审核）；
  2. 把审核通过的信息模板**关联到 `shanwood.cn`**（阿里云域名控制台 → 域名列表 → 操作列「管理」→ 基本信息 → 联系人邮箱右侧「更改(过户)」→ 快速过户 / 普通过户）。
- 个人材料：身份证**人像面**彩色原件照即可，仅在系统明确提示或审核失败时才需正反面合并为一张图。
  - 格式 JPG / JPEG / PNG / BMP / HEIC / WebP，**55 KB – 5 MB**；四角完整、无遮挡、无反光；**禁止 PS 修改**；格式不符要另存为正确格式，**不要直接改文件后缀名**。
- **免费**；审核通过后域名约 **1–2 个工作日**解锁。
- 查状态：阿里云「域名信息查询（WHOIS）」看是否还有 `serverHold` / `clientHold`。若出现 `clientHold`，多半是联系人邮箱未验证或用了公共模板邮箱 `zyhl-admin@list.alibaba-inc.com`，按上面「更改(过户)」换成已实名模板。
- ⚠️ **域名实名认证 ≠ ICP 备案**。本项目走境外 Pages 托管，完成实名后依法无需备案。
- 顺手开启**自动续费**（按 ¥42 扣，防 `.cn` 忘记续费进赎回期 ¥1200），并在 2027-10 月底设日历提醒，先查双 11 续费活动再决定是否手动续。

### 2. 把域名接入 Cloudflare（阿里云精确路径 + 前置检查）

#### 2.1 改 NS 之前的前置检查（官方要求，防切换期间解析中断）

1. **解析记录同步**：按 2.2 的第 1–2 步先在 Cloudflare 建好 zone，并配齐完整解析记录。改 NS 后，只有 Cloudflare 里的记录生效，阿里云「云解析 DNS」里的记录会全部失效。

   **本站改 NS 前，在 Cloudflare DNS 里照抄这几条：**

   | 类型 | 名称 | 内容 | 代理状态 | 用途 |
   |---|---|---|---|---|
   | A | `@`（即 `shanwood.cn`） | `192.0.2.1` | **已代理（橙云）** | 占位记录，让「裸域 301 → sequoia」的 Redirect Rule 有承载点；`192.0.2.1` 是 RFC 5737 保留地址，不会真回源 |
   | A | `dl` | `192.0.2.1` | **已代理（橙云）** | 占位记录，供 `dl.shanwood.cn` 301 → GitHub Release |
   | CNAME | `sequoia` | **不要手工加** | — | Pages 项目绑自定义域时自动写入 |
   | CNAME | `blog` | **不要手工加** | — | 同上 |
   | MX / TXT | — | 本站无邮箱服务，全部留空即可 | — | 官方前置检查里的 MX 针对有邮件业务的域名，本项目不涉及 |

   - ⚠️ Cloudflare `Add a site` 会**扫描并导入阿里云现有记录**：新注册域名常被塞了默认停放页 A 记录 / 泛解析，扫描结果里**把这些默认记录删掉**，别带进 Cloudflare。
   - Pages 的 `sequoia` / `blog` CNAME 由 Cloudflare 自动创建并代理，**手工重复加同名记录会冲突**（第 3 节已强调）。
   - 先建好这两条占位 A 记录再改 NS，就能满足下面第 2 步的 `dig @<Cloudflare-NS> shanwood.cn A` 验证，改 NS 后不会出现「无记录可解析」的空窗。

2. **解析生效验证**：直接向新 NS 查询，确认它能正确响应（本站无邮箱服务，`MX` 那条可跳过）：
   ```bash
   dig @<Cloudflare-NS> shanwood.cn A
   dig @<Cloudflare-NS> shanwood.cn MX   # 仅当域名有邮件业务时需要
   ```
3. **检查并关闭 DNSSEC**：`dig +dnssec shanwood.cn`，响应里含 `RRSIG` 说明已启用，必须**先到注册商处删除 DS 记录并关闭 DNSSEC**，否则改 NS 后域名会解析失败。新注册域名一般未启用，可跳过。
4. **降低 TTL（推荐）**：若已有旧解析，提前 24–48 小时把关键记录 TTL 降到 300 / 600 秒，等旧 TTL 过期后再改 NS，便于快速回滚。本站是新域名、无历史解析，此步可跳过。
5. **填写规则**：至少 2 个 NS；`.cn` 属 CNNIC 域名，最多可填 6 个；**不要带空格或特殊字符**。Cloudflare 给 2 个，直接填即可。
6. **不能改 DNS 的两种状态**：域名处于续费宽限期 / 赎回期 / 转移期，或未实名被 `serverHold`。✅ **本域名两项均已排除**（新注册、实名已通过），现在可以直接改 NS。

#### 2.2 照着点：阿里云改 Nameserver

| 步 | 位置 | 动作 |
|---|---|---|
| 1 | Cloudflare 控制台 | `Add a site` → 输入 `shanwood.cn` → 选 **Free** 计划 |
| 2 | Cloudflare 站点初始化 | 扫描并确认现有解析记录（新域名基本为空），**复制分配的 2 个 nameservers**（形如 `xxx.ns.cloudflare.com`） |
| 3 | 阿里云 → **域名列表** | 定位 `shanwood.cn`，点操作列 **「管理」** |
| 4 | 左侧导航栏 | **`DNS 管理 > DNS修改`** → 点 **「修改DNS服务器」** |
| 5 | 弹出表单 | 找到 **「修改为自定义DNS」** 区域，填入两个 Cloudflare NS（需更多点 `+添加DNS`）→ 点 **「确定」** |
| 6 | 「安全验证」对话框 | 点 **「获取验证码」**，填入手机短信或邮箱验证码 → 提交，修改生效 |
| 7 | Cloudflare 站点概览 | 等 zone 从 `Pending Nameserver Update` 变 **`Active`**（几分钟 ~ 48 小时） |

- 批量路径（以后加域名时）：域名列表勾选多个 → 页面下方 **更多 > DNS修改** → 输入自定义 DNS → 短信验证 → 在「批量操作记录详情」看结果。
- 官方入口参考：阿里云帮助中心《修改DNS服务器》`help.aliyun.com/zh/dws/user-guide/modify-dns-server`。

#### 2.3 改完别慌 & 生效验证

- ⚠️ 阿里云「云解析 DNS」控制台可能提示 **「未使用系统分配 DNS / Assigned NS not used」** 或 `Query NS failed`。阿里云官方明确：**在阿里云注册、改用第三方权威 DNS（如 Cloudflare）时这是预期的正常状态**，在阿里云控制台加的解析记录本来就不会生效。**不要因此把 NS 改回去。**
- 生效验证：
  ```bash
  dig shanwood.cn NS                    # 应返回两个 *.ns.cloudflare.com
  dig @<Cloudflare-NS> shanwood.cn A    # 验证新权威 DNS 能响应
  ```
  Windows 本机仍看到旧结果可 `ipconfig /flushdns`；全球完全生效最长 48 小时，部分地区短暂异常属本地 DNS 缓存，耐心等即可。
- 域名在**阿里云注册**才可以改 NS；若域名是在 Cloudflare Registrar 注册的则**不允许改 NS**（会锁死）。本路线成立的前提正是注册商不是 Cloudflare。
- 备注（2026-07 工信部 DNS 服务商资质核查）：**已完成 ICP 备案的商用域名**要求主 NS 用持牌国内服务商，境外 DNS 只能作备用副解析。本项目走免备案路线、不触发该核查；**若将来改走备案路线，需把 NS 换回阿里云/腾讯云 DNS**。
